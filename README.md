
# NDRMS | AI 기반 재난 피해 심사 및 지원금 산정 지원 플랫폼

KT AIVLE School 팀 프로젝트로 진행한 AI 기반 재난 피해 심사 지원 서비스입니다.

본 저장소는 프로젝트의 전체 소스코드를 복제한 저장소가 아닌, **개인 담당 업무와 서비스 기획·개발 및 문제 해결 경험을 정리한 프로젝트 포트폴리오**입니다.

## 1. 프로젝트 개요

자연재난 피해 신고부터 AI 기반 피해등급 분석, 담당자 심사, 지원금 산정 및 보고서 생성까지 이어지는 행정 업무를 지원하는 플랫폼입니다.

AI가 피해등급 후보와 판단 근거를 제공하고, 최종 결정은 담당자가 검토하도록 설계하여 행정 업무의 효율성과 판단 과정의 투명성을 높이는 것을 목표로 했습니다.

### 기획 방향

초기에는 AI를 활용한 피해등급 자동 판정을 중심으로 검토했습니다. 그러나 실제 행정 업무에서는 담당자의 최종 판단과 판정 근거 확인이 중요하다는 점을 고려했습니다.

이에 팀원들과 함께 서비스 방향을 재검토하고, **AI가 담당자의 의사결정을 지원하는 구조**로 기획 방향을 전환했습니다.

기술을 통해 담당자의 판단을 대체하기보다, 실제 업무에 필요한 정보와 판단 근거를 제공하는 데 중점을 두었습니다.

## 2. 주요 기능

- 피해 신고 정보 조회 및 관리
- 피해 이미지 기반 AI 분석 결과 제공
- 담당자 피해등급 심사 및 승인
- 피해등급에 따른 지원금 산정
- 심사 결과 및 보고서 생성

## 6. 문제 해결 경험

### API 요청 경로 불일치 문제

**문제 상황**

프론트엔드에서 API를 호출했으나 일부 요청이 정상적으로 처리되지 않는 문제가 발생했습니다.

**확인 과정**

- Chrome 개발자 도구의 Network 탭에서 요청 URL과 응답 상태 확인
- Swagger에 정의된 API 경로와 실제 프론트엔드 요청 경로 비교
- 프론트엔드와 백엔드의 경로 불일치 확인

**대응**

- 프론트엔드에서 발생한 오류는 직접 수정
- 백엔드 수정이 필요한 부분은 확인한 내용을 담당 팀원에게 전달
- 팀원과 API 연동 사항을 공유하며 수정 과정에 협력

**배운 점**

문제의 발생 지점을 구분하고 재현에 필요한 정보를 정확하게 전달하는 것이 효율적인 오류 해결과 협업에 중요하다는 점을 배웠습니다.

## 7. 프로젝트를 통해 배운 점

이번 프로젝트를 통해 서비스 기획에서는 기술의 활용 가능성뿐 아니라 실제 사용자의 업무 환경과 절차를 이해하는 것이 중요하다는 점을 배웠습니다.

초기 자동 판정 중심의 방향을 담당자의 의사결정을 지원하는 서비스로 전환하면서, 사용자의 역할과 판단 과정을 고려한 기획의 중요성을 경험했습니다.

또한 Figma를 활용한 UI 설계부터 React 기반 화면 구현, API 연동까지 경험하며 기획한 기능이 실제로 동작하기 위해 필요한 데이터 흐름과 개발 과정에 대한 이해를 넓혔습니다.

Jira를 활용해 업무별 담당자를 지정하고 진행 상태를 관리하면서, 팀 프로젝트에서는 개별 작업의 진행 상황을 공유하고 협업 과정에서 발생하는 문제를 조율하는 일이 중요하다는 점도 배웠습니다.

특히 **업무 프로세스 분석 → 서비스 기획 → UI 설계 → 화면 구현 → 개발 협업**으로 이어지는 과정을 경험하며, 사용자 요구사항과 기술적 구현 가능성을 함께 고려하는 역량을 키웠습니다.

이 경험을 바탕으로 실제 업무에 필요한 기능을 정의하고, 사용자와 개발자 모두의 관점을 이해하는 IT 서비스 기획자로 성장하고 싶습니다.
